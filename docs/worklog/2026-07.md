## 2026-07-04 — Select ergonomics: full-width triggers, content-safe menus, padded lists

**What:** Three owner-reported issues with select menus, fixed in
`ui/select.tsx` so every consumer inherits them:
1. **Trigger width** — stock `w-fit` made selects hug their value ("corn ˅")
   while sibling inputs filled the form column. Now `w-full`, matching
   `Input`; compact call sites keep their explicit widths (tailwind-merge
   lets `w-40`/`w-28`/`w-auto` win).
2. **Menu width** — the popup was pinned to the trigger width
   (`w-(--anchor-width)` + `overflow-x-hidden`), so options wider than the
   trigger clipped. Now `min-w-[max(var(--anchor-width),9rem)]`: never
   narrower than the trigger or 144px, free to grow to its content.
3. **Internal padding** — items sat flush against the popup edge (the
   focus highlight bled into the rounded corner). The item list now
   carries `p-1` (moved off `SelectGroup` so bare items get it too) and
   items are `py-1.5 pl-2`.
**Verified:** headless — record-form Grain trigger 264px = its column,
menu ≥ trigger with 4px insets and no clipped item text; 112px operator

## 2026-07-04 — Modal patterns (decision 0008, pattern 4)

**What:** Fourth UI pattern, both surfaces, experimental: **Modals** —
deliberately about *configuration axes*, not use cases (owner direction:
"don't think about the domain so much — the various ways modals can be
configured and designed"). Four axes, each with working portal demos and
static open-state preview mirrors:
1. **Size ladder** — xs (confirms) / sm default (messages) / md (forms to
   ~6 fields) / lg (review surfaces); past lg the task deserves a page.
   All sizes collapse to the same near-full-width sheet on phones.
2. **Footer configurations** — standard (dismiss + commit right-aligned),
   split (rare third action anchored left with `sm:mr-auto`, away from
   the commit pair), stacked (full-width, primary first, for one clear
   recommendation). All collapse to stacked on phones via the footer's
   built-in `flex-col-reverse sm:flex-row`.
3. **Scrolling** — body content scrolls in a capped bordered region
   (`max-h + overflow-y-auto`); title/actions never move; cap the body,
   never the popup.
4. **Dismissal** — dismissable default (✕ / Escape / scrim click) vs
   *must-choose*: `showCloseButton={false}` + Base UI
   `disablePointerDismissal` + a controlled `onOpenChange` that refuses
   every close reason except explicit Close buttons (Base UI has no
   Radix-style `onInteractOutside`; reason strings checked
   case-insensitively for "close"/"imperative").
Wired: portal.tsx, app-sidebar (AppWindow, exp pill), component-meta,
preview section + nav ("Modals") + status table, legend 10 → 11. Preview
reuses `.dialog-scrim`/`.dialog`/`.dialog-foot` with inline variants —
zero new CSS.
**Verified (interaction, headless):** lg renders 512px; Escape closes the
default dialog; scroll body overflows its cap; must-choose refuses Escape
and outside click, has no ✕, and exits via the explicit button; zero page
errors. Screenshots both surfaces; mobile-audit clean; tsc/build/lint
green.
