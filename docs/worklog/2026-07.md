## 2026-07-03 — Fix mobile horizontal overflow (both surfaces)

**What:** Eliminated all horizontal page overflow at phone widths.
Reported on iPhone Chrome: horizontal scroll, pinch-zoom showing a wider
page, sticky top bar appearing to shrink — all one root cause, the document
being wider than the viewport (474px at a 390px screen). Portal fixes:
added explicit `grid-cols-1` to all 24 responsive grids (implicit auto
columns size to max-content and blow out the page), `minmax(0,1fr)` +
mobile stacking for the typography specimen rows, `flex-wrap` +
`min-w-0`/`overflow-x-auto` for the table segmented controls, and
`overflow-x-auto` on the saved-views tab strip. Preview (same bug class):
`.grid-2 > * { min-width: 0 }`, `flex-wrap` on `.pagination` and
`.dt-control`, `overflow-x-auto` on `.views`, `minmax(0,1fr)` + mobile
stack for `.tstyle-row`, `max-width: 100%` on `.navmenu-panel`. Verified
with a Playwright overflow scanner (element rects + text-node ranges,
clip-aware) at 375px and 390px: both surfaces now measure exactly
viewport-width with zero unclipped offenders. Added a mobile-overflow
convention to CLAUDE.md so new work doesn't reintroduce the pattern.
**Why:** User-reported bug on iPhone Chrome.
**Touched:** `portal.css`, `CLAUDE.md`, `kernel-portal/src/components/portal/`
(`foundations.tsx`, `tables.tsx`, `filters.tsx`, and the mechanical
`grid-cols-1` sweep across all portal section files).
