## 2026-07-04 — Select ergonomics: full-width triggers, content-safe menus, padded lists

**What:** Three owner-reported issues with select menus, fixed in
`ui/select.tsx` so every consumer inherits them:
1. **Trigger width** — stock `w-fit` made selects hug their value ("corn ˅")
   while sibling inputs filled the form column. Now `w-full`, matching
   `Input`; compact call sites keep their explicit widths (tailwind-merge
   lets `w-40`/`w-28`/`w-auto` win).
2. **Menu width** — the popup was pinned to the trigger width
   (`w-(--anchor-width)` + `overflow-x-hidden`), so options wider than the
   trigger clipped. Now `min-w-[max(var(--anchor-width),9rem)]`: never
   narrower than the trigger or 144px, free to grow to its content.
3. **Internal padding** — items sat flush against the popup edge (the
   focus highlight bled into the rounded corner). The item list now
   carries `p-1` (moved off `SelectGroup` so bare items get it too) and
   items are `py-1.5 pl-2`.
**Verified:** headless — record-form Grain trigger 264px = its column,
menu ≥ trigger with 4px insets and no clipped item text; 112px operator

  `tabular-nums` the digits still line up, and these columns hold same-width
  signed basis values (`-0.27`, `+0.05`) where right-alignment buys little.
  Covers Rank, Bids, the five basis columns in the inset, and the three currency
  columns on Scenarios. Action clusters stay right-aligned — those are controls
  at the row end, not numbers.

**Contrast checked, because lightening body-size text is exactly where AA
breaks:** the portal's `contrast-audit` only covers DS tokens, so a
prototype-layer change is invisible to it. Measured the painted colours directly
— header on card is **5.79:1 dark / 5.15:1 light** at 14px/400, both clear of
AA's 4.5:1; data stays 14.34:1 / 17.5:1.

Worth recording: the first measurement reported 1.01:1 and "FAIL". That was the
harness, not the design — the helper read `getComputedStyle` colour strings with
`match(/[\d.]+/g)`, which on an `oklch()` value grabs the L/C/H components and
treats them as RGB 0-255. Re-measured by painting each colour onto a 1×1 canvas,
which converts any CSS colour to real sRGB bytes. Anything comparing colours
in a browser should use the canvas route.
