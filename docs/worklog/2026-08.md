## 2026-08-02 — Name the object and domain levels that only existed as code

**What:** Wired the two domain entities that had shipped with empty `relationships` and empty `sourceFiles` since they were created - `domain.contract-detail` and `domain.settlement-statement` now point at `kernel-portal/src/components/portal/contract-detail.tsx` and `settlement.tsx`, and relate down the ladder to `element.tables`, `element.form-elements`, and `object.record`. Registered two objects that were already built in the portal but never named: `object.expandable-row` (`portal/tables.tsx`) and `object.page-section` (`portal/section.tsx`), with `domain.settlement-statement composedWith → object.expandable-row` recording the containment. Catalog moves 93 -> 95 entities and 81 -> 83 documentation records; the pinned counts in `check-catalog.mjs` move with them.

**Why:** The catalog had a level ladder in its `kind` enum - component, element, object, pattern, domain - but the top two rungs were barely wired. Both domains were registered names with nothing attached, so nothing in the catalog knew that a settlement statement is built out of tables and expandable rows, or that either domain had an implementation at all. Naming the two objects follows the same rule the drift register uses for the prototype: something built twice and reused is an entity whether or not anyone has registered it. Decision 0057 records the ladder, the registration rule it implies, and the fact that three Kernel levels collapse into one DSDS kind on export.

**The approximation worth recording:** three of these relations are the wrong relation, deliberately. `domain.contract-detail dependsOn object.record` is really *extends* - a domain specialising an object - and `composedWith object.expandable-row` is really *part-of*. Kernel's `relationshipTypes` is `composedWith | dependsOn | usedBy | recommendedPatterns`, while DSDS 0.15.2's canonical set is `depends-on | composes | part-of | alternative-to | replaces | extends`. Containment and specialisation are both inexpressible today, so they flatten into `composedWith`/`dependsOn` and the level distinction is lost in the data. Using the existing vocabulary rather than inventing one keeps the export contract stable; the flattening is the concrete argument for adding `part-of` and `extends`, which is now an open question rather than a hypothetical.

**Verified:** `catalog:check` green (`95 entities, 83 documentation records, 0 violations`) - its source-resolution loop passing is the proof the four backfilled paths exist. `ds:doctor` green (9 checks, 0 violations) after `agents:generate` refreshed the three stale inventory blocks. `sourceFiles` was set by script: `ds:add` always writes it empty and no CLI command sets it.

**Touched:** `docs/decisions/0057-catalog-kinds-are-a-level-ladder.md`, `packages/catalog/src/entities.ts`, `kernel-portal/scripts/check-catalog.mjs`, `AGENTS.md`, `packages/catalog/AGENTS.md`, `kernel-portal/AGENTS.md`, `docs/STATE.md`, `docs/worklog/2026-08.md`.

## 2026-08-04 — Findings from a second consumer, brought back to the DS

**What:** Eight fixes and two additive changes found by building a second app (the v2 prototype) against `@kernel/ui`, applied here on their own branch off `main`, with no prototype design decisions attached.

The fixes: `SidebarInset` gains `min-w-0`, so wide content scrolls inside its column instead of pushing the page out from under the sidebar. Tab hover is inactive-only in all three variants — the active tab is the destination, not somewhere to move to. A button with a leading or trailing glyph trims its padding on the icon side, replacing a `data-icon` attribute only `pagination.tsx` ever set and a `has-[>svg:first-child]` selector that could not tell a leading icon from a trailing one. `Table` gains a `striped` prop whose selector is `[&>tbody>tr:nth-child(even)]` — child, not descendant, so a nested table in a detail row is not striped on its own parity. `select-trigger` joins decision 0007's coarse-pointer extension lists (it renders its own button element, so the button rule never reached it) and `tabs-trigger` grows to 44px instead, because triggers sit edge to edge and a sideways extension would land on a neighbour. The reduced-motion guard zeroes delays as well as durations. The elevation ramp gets per-theme alpha and a monotonic `2xl`, and derives from `--shadow-color`, which had been declared since the token sheet was written and referenced by nothing.

**Why:** A design system's own gallery exercises its components the way the gallery was written; a second application exercises them the way an application does. Every item here is a defect that only appeared under that second use — dark mode had no working elevation at any rung, the top of the ramp cast a smaller shadow than the middle of it, and two touch-target slots had been missed by both decision 0007 and decision 0009. None of them depend on the prototype's design direction, so they travel without it.

**Touched:** `packages/ui/src/components/ui/{sidebar,tabs,icon,button,table}.tsx`, `packages/ui/src/styles.css`, `kernel-portal/src/components/portal/foundations.tsx`, `kernel-portal/src/lib/component-docs/table.ts`, `kernel-portal/scripts/mobile-audit.mjs`, `docs/decisions/0053-elevation-ramp-per-theme-alpha.md`, `docs/decisions/0054-tinted-shadow-color.md`, `docs/worklog/2026-08.md`, `docs/STATE.md`.
