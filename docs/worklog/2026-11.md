## 2026-11-07 — Portal gets global search (Ctrl/Cmd-K palette)

- **What**: A command palette over every rail page and every component page, opened
  from a search trigger in the portal header or Ctrl/Cmd-K. Built on Kernel's own
  `CommandDialog` + `Kbd`; the sidebar `nav` data and `galleryClusters` are the
  index, so new pages and components appear in search with zero extra wiring.
- **Why**: The shell had no working search — the only "Search" in the rail was the
  Query object page. Dogfooding `CommandDialog` also surfaced a real library bug.
- **Fixed in @kernel/ui**: `CommandDialog` crashed on open ("reading 'subscribe'"):
  `DialogTitle`/`DialogDescription` rendered outside `DialogContent` (Base UI needs
  them inside the popup) and palette children were not wrapped in a `Command` root,
  so cmdk's store never existed. Never caught before because the gallery only demos
  inline `Command`. Patch changeset recorded; palette widened to the lg dialog width.
- **Touched**: `kernel-portal/src/components/portal/command-search.tsx` (new),
  `app-sidebar.tsx` (exports `nav`/`NavItem`), `pages/portal-layout.tsx` (header
  trigger), `packages/ui/src/components/ui/command.tsx` (CommandDialog fix),
  `.changeset/kernel-ui-patch-command-dialog.md`.
- **Verified**: portal `tsc -b` + vite build clean; check-component-docs 86/0;
  style-fidelity OK; oxlint 0 errors; headless Playwright proof — trigger + Ctrl+K
  open the palette, "map grammar" navigates to /map-grammar, "toggle" navigates to
  /components/toggle.
