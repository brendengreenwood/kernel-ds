# 0046 — Generated agent guidance: bounded AGENTS inventories and DS lifecycle skills

**Status:** accepted
**Date:** 2026-07-30

## Decision

Agent-facing guidance is split into two layers with a hard boundary:

1. **Hand-authored prose** in AGENTS.md files stays curated and is never generated over.
2. **Derived inventories** (catalog counts, package export entries, DS scripts, skills, generate/verify/doctor registries) live only inside bounded marker sections — `<!-- kernel-ds:generated:start -->` … `<!-- kernel-ds:generated:end -->` — regenerated by `npm run agents:generate` and checked by `npm run agents:check`.

The DS lifecycle is additionally encoded as nine skills under `.agents/skills/` (`kernel-ds-use`, `-component`, `-pattern`, `-definition`, `-document`, `-verify`, `-release`, `-upgrade`, `-audit`), statically validated by `npm run skills:check`: frontmatter integrity, a required Verification section, no private-path leaks, and every referenced repo path, npm script, and catalog entity must actually exist. Request fixtures assert each skill wins uniquely for its trigger phrases.

## Why

Inventories drift the moment they are hand-maintained; prose loses its judgment the moment it is generated. Splitting the two lets generation keep facts current (decision 0039's colocated-AGENTS pattern, now derived from the catalog and package APIs) while authorship keeps the rules. Skills referencing deleted scripts or renamed entities silently rot — static validation turns that rot into a failing gate.

## Consequences

- `agents-inventories` is a registered `ds:generate` step; `agents-freshness` and `skill-integrity` are registered `ds:doctor` checks.
- The marker applier preserves everything outside the markers byte-for-byte and refuses unbalanced markers (proven red/green in `scripts/ds/__check__.mjs`).
- Strict skill validation applies to `kernel-ds-*` skills; legacy `kernel-*` skills predate the conventions and delegate to the new commands instead.
