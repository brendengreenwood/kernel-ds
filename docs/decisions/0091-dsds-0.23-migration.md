# 0091 — Pin DSDS 0.23.1 and emit the entries-based document format

- Date: 2026-11-08
- Status: accepted

## Context

Kernel pinned DSDS 0.15.2 (decision 0063) and generated a single-entity compatibility
document (`dsdsVersion` + `entity`). Upstream moved on: the npm distribution channel was
unpublished (the old `dsds:status` source now 404s), the spec restructured its document
format in 0.20+, and the current release is 0.23.1. The 0.23 format replaces
`dsdsVersion`/`entity`/`documentBlocks` with a root of `schemaVersion` + `name` +
`entries[]`, requires `id`/`kind`/`name`/`description` per entry, drops the `pattern`
kind, and supports namespaced custom kinds (e.g. `acme.icon-library`).

## Decision

- Re-vendor the official bundle at 0.23.1 (tag commit `6384190f…`, schema now at
  `schema/dsds.bundled.schema.json` upstream) via the existing `dsds:update` flow;
  provenance, SHA-256 integrity, and offline validation discipline are unchanged.
- Bump the compatibility contract to version 3. The generated document is a 0.23
  `entries[]` document. Kernel kinds map explicitly: `component`/`element` →
  `component`; `pattern`/`object`/`domain` → namespaced custom kinds
  `kernel.pattern`/`kernel.object`/`kernel.domain` (the taxonomy is no longer flattened
  into DSDS's removed `pattern` kind). `identifier` becomes `id`; every entry carries a
  deterministic `description` synthesized from the entity name and kind. All catalog and
  prototype metadata stays lossless under the `com.kernel.catalog` and
  `com.kernel.prototype` extension namespaces.
- `dsds:status` defaults to the upstream repository's `package.json` on `main` (the npm
  package no longer exists). Explicit `--source` descriptors still work.

## Consequences

- `dsds/contract-sample.dsds.json` validates against the official 0.23.1 bundle offline;
  the `ds:check` matrix exercises generate/check/status/update red paths against 0.23-era
  fixtures (`update-0.24.0`, refreshed `upstream-*` descriptors).
- Kernel's slug identifiers (decision 0055) remain valid: 0.23's id pattern is looser
  than our `^[a-z][a-z0-9-]*$` rule, which we keep as the stricter contract.
- Future spec bumps route through `dsds:update` with a descriptor pointing at a tag
  commit; migration guidance is captured from the upstream CHANGELOG (the spec no longer
  ships a standalone migration guide).
