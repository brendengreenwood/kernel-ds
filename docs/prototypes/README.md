# Prototype lifecycle

`docs/prototypes/registry.json` is the canonical concern-level ledger for discoveries made in Figma and `kernel-app`. Use the deterministic lifecycle command instead of editing registry state by hand:

```bash
npm run ds:prototype -- check
npm run ds:prototype -- status
npm run ds:prototype -- add ...
npm run ds:prototype -- link ...
npm run ds:prototype -- set ...
npm run ds:prototype -- project
```

Commands refuse invalid changes before writing, preserve bytes on no-ops, and atomically replace changed files. `set` records completed canonical work; it never edits `@kernel/ui` or `@kernel/definitions`.

## Promotion sequence

New canonical implementation requires three commits:

1. Implement and verify the canonical `@kernel/ui` or `@kernel/definitions` work, then commit it.
2. Record the tuple-specific acceptance artifact under `docs/prototypes/acceptances/`, referencing the immutable implementation commit, then commit the artifact.
3. Run the `validated → promoted` transition against both committed artifacts, regenerate projections, verify, and commit the registry/projections.

Never invent acceptance from an actor name or generic approval. A shallow checkout that cannot resolve retained history is a non-success state; fetch the required history before promotion.

`docs/prototypes/status.md` is generated by `npm run ds:prototype -- project` and freshness-checked by `ds:prototype check` and `ds:doctor`.
