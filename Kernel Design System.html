Foundations

Motion

One source for timing and easing (decision 0018) so polish stays consistent and tunable — animate with the tokens, never ad-hoc ms or curves. All motion honors prefers-reduced-motion. Richer engines (animated numbers, list transitions, enter/exit) are opt-in npm libraries, portal-only.

Duration — how long

Three steps. Faster for small state flips, slower for enter/exit and layout. Click a track to replay.

--duration-fast120ms
--duration-base200ms
--duration-slow320ms
Easing — the curve

Decelerate for most UI, symmetric for moves, a little overshoot for playful affordances. Same duration, different feel.

--ease-outmost UI
--ease-in-outsymmetric
--ease-springovershoot
Reduced motion
Both surfaces carry a @media (prefers-reduced-motion: reduce) guard that near-zeros durations everywhere. New motion inherits the guard for free — you never opt in to accessibility.
Polish primitives portal-only

Opt-in engines wired to the same tokens — animated numerics (@number-flow/react), list transitions (@formkit/auto-animate), and enter/exit + layout (motion). React-only, so this static preview documents the tokens and shows the content without the motion; see the portal for the live effect.

Navigation

A pricing tool grows areas — origination today, accounting tomorrow — so navigation has to scale by adding entries, not redesigning. Three levels, three patterns: a module switcher for areas, a grouped rail for destinations within an area, and underline tabs for views within a record.

Grouped rail · nested destinations

A destination is an icon, a label, and optionally a live count. Related destinations sit under a group label; a destination with sub-views nests one level of children — never deeper. Extending the app is adding an entry or a group here, nothing else moves.

Patterns

Advanced filtering

Quick chips answer the everyday questions; a pricing desk also asks compound ones — corn under −0.15 basis delivering before November. The builder composes those conditions, column controls shape the table, and date presets speak the domain’s calendar. Saved views (see Filtering & views) persist the result.

Filter builder

One row per condition — field, operator, value — joined with And. Operators change with the field type; the footer shows the match count live so a bad filter is obvious before it’s applied. Reach for the builder past three conditions; below that, chips win.

Origination flow

The origination loop: a producer offers grain at a target price, the merchant counters or books, and a booked offer becomes a contract. Three surfaces — a work queue that ranks the decisions, a counter composer that keeps the market math in view, and a negotiation thread that becomes the audit trail.

Offer queue

The queue leads with the decision: offer vs. current bid, in mono, side by side. An offer at or under the bid emphasizes Book; above it, Counter. An offer stays pending while a counter is out — the counter itself is an event (outline badge), not a lifecycle state. Expired rows mute and offer a renew.

Modal patterns

One dialog component, four axes of configuration: how wide and tall it is, how the header and footer bars arrange themselves, what scrolls when content is long, and which ways out exist. Pick a point on each axis deliberately — the combinations below cover nearly every modal an app needs, up to entire flows.

Width ladder

Five stops: xs for confirms, sm for messages, md for forms, lg for review surfaces, xl for flows and workspaces. Size to the content’s natural width, then stop. On phones every width becomes the same near-full-width sheet.

An xs dialog
width="xs" · confirms — a sentence and two buttons.
An md dialog
width="md" · forms up to ~6 fields. lg adds room for review; xl is the flow canvas.
Header & footer bars

The header is its own bar — title, context, and the ✕ live there, visually separated from the work. Footers come in three arrangements: standard (dismiss + commit, right-aligned), split (a rarer third action anchored left, away from the commit pair), and stacked (full-width buttons for one clear recommendation). All collapse to stacked on phones. The primary always names its verb — never “OK”.

Standard
Dismiss beside commit, right-aligned — the primary hugs the corner where the eye finishes.
Split
The rare third action anchors left, physically separated from the commit pair so it can’t be hit by momentum.
Stacked
One clear recommendation: full-width buttons, primary first.
Height & flows

Width is only half the frame. auto height hugs the content; tall fixes the frame for feeds and histories; full turns the modal into a canvas — entire flows run inside it, with the header bar carrying progress and the footer navigating steps. Fixed heights scroll their body region. If a flow outgrows even that, it’s a page.

Scrolling

In an auto-height modal, long content scrolls in a capped, bordered body region; the title and actions never move. Cap the body, never the popup — the dialog itself must not exceed the viewport.

Dismissal

Default is generous: ✕, Escape, and scrim click all cancel safely. A must-choose modal removes them and offers only explicit actions — legitimate only when abandoning would lose real work, and even then one of the choices must be an exit. Never nest modals.

Install & usage

Kernel is a Tailwind v4 token layer for shadcn/ui — components on Base UI (base-nova), icons from MDI, native fonts only. There's no package to add: the token layer in this repo is the source of truth. Drop it into a shadcn project and every component re-themes.

1 · Start from a shadcn/ui project
terminal
# a Tailwind v4 + shadcn/ui project (components on Base UI, base-nova style)
npm create vite@latest my-app -- --template react-ts
npx shadcn@latest init
2 · Drop in the Kernel token layer
globals.css
/* globals.css / index.css */
@import "tailwindcss";

/* Paste Kernel's token layer here — the full :root, .dark, and
   @theme inline blocks from step 5. That layer IS Kernel; every
   shadcn component re-themes off it. Native system fonts only. */
3 · Add the components
terminal
npx shadcn@latest add accordion alert alert-dialog aspect-ratio avatar \
  badge breadcrumb button calendar card carousel chart checkbox collapsible \
  command context-menu dialog drawer dropdown-menu form hover-card input \
  input-otp label menubar navigation-menu pagination popover progress \
  radio-group resizable scroll-area select separator sheet sidebar skeleton \
  slider sonner switch table tabs textarea toggle toggle-group tooltip

Components resolve to base-nova (Base UI), not Radix. Generated files import lucide-react — redirect those to the MDI shim (it exports the same glyph names):

tsx
// Kernel icons are MDI, not lucide (decision 0019)
import { Search, ChevronRight } from "@/components/ui/icon"
