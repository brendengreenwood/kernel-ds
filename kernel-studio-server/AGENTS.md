Mastra dev server. Generative design agent authoring against the ds-bundle. Not shipped to users
Run all commands from kernel-studio-server/ (npm, not pnpm). TypeScript, ESM, Node 24

Test: npm test (vitest run) — 109 tests / 10 files today, all must pass
Typecheck: npm run check (tsc --noEmit)
Dev server: npm run dev (mastra dev) — Mastra playground + agent runtime, port 4111
API only: npm run api (tsx src/api/index.ts)
vitest tests are colocated with source (*.test.ts) plus src/__tests__/
Run the narrowest focused test file for the area you changed before the full suite; run npm test + npm run check before a PR

Depends on the repo-root ds-bundle (../ds-bundle) for component docs, tokens, and composition the agents read
The bundle is generated by kernel-portal/scripts/build-ds-bundle.mjs — if a tool can't find guidance, rebuild it from the portal, don't hand-author bundle files
Path resolution is centralized in src/lib/paths.ts — repoRoot() walks up to the dir holding ds-bundle/components/general
Cross-package paths (all env-overridable): dsBundleDir → ../ds-bundle, definitionsDir → ../kernel-portal/public/definitions (agent-authored JSON persists here, decision 0033), prototypesDir → ./prototypes
Overrides: KERNEL_STUDIO_REPO_ROOT, STUDIO_DEFINITIONS_DIR, STUDIO_PROTOTYPES_DIR (tests set these to temp dirs)

Architecture (src/)
mastra/ — the Mastra runtime (see mastra/AGENTS.md). index.ts is the config hub: registers agents, tools, workflows, storage
mastra/mcp-server.ts — MCP server exposing studio capabilities
mastra/agents/ — toolsmith (authors object-model + workspace definitions), design, research, artifact, supervisor
mastra/tools/ — tool families: define (validate/write definitions), ds-bundle (read component docs/design docs), diagram (ir + compiler), artifact, brief, cognition, observation, ontology, persona, quote, rag, transcript
mastra/workflows/ — artifact-workflow, cognitive-research-workflow (step-based, suspend/resume)
mastra/storage/ — libsql-backed stores (artifact, evidence, observation, ontology, persona, quote, snapshot, transcript) + db.ts
mastra/rag/ — transcript-rag (semantic recall over transcripts)
mastra/processors/, mastra/evals/ — input/output processors and eval harnesses
mastra/routes/, mastra/public/ — server routes and static assets
api/ — hono HTTP layer (api/routes/)
contract/ — schema shared with the portal object model
__tests__/ — cross-cutting vitest suites (contract, tools, define-tools)

Keep tool contracts stable — the agents and the portal chat bridge call them; changing a tool signature ripples to both
